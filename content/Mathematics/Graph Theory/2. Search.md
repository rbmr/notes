### Traversals vs Search

- A **graph traversal** is the process of visiting each vertex in a graph. 
- Informally, a graph traversal comes down to the following:
	- The **frontier** (also called the fringe or open set) is the collection of candidate nodes for expansion. **Expansion** is the process of picking a node from the frontier, processing it, and adding its adjacent nodes back to the frontier.
	- Graph traversals then come down to repeated expansion. The main aspect by which they differ being the order in which they expand nodes from the frontier.
	- We frequently maintain a set of visited or discovered nodes (also called the closed or explored set). This allows us to ensure we dont process the same vertex multiple times (or an infinite number of times if the graph contains cycles)
- A **tree traversal** is the process of visiting each vertex in a tree, starting from a root node. Uniquely, there exists exactly one path from the root to any node, consequently eliminating the need for a visited set. 
- A **graph search** is a special case of a graph-traversal. While a traversal is about visiting each vertex in a graph, a search is designed to traverse only until it reaches some goal (or "finds a solution"). 
	- A search algorithm is **complete** if it is guaranteed to find a solution if it exists.
	- A search algorithm is **optimal** if it is guaranteed to find the "best" solution with respect to some objective function, generally represented as minimizing the sum of edge weights.
- A **search tree** (in the context of graph search) is a tree where the root is the starting node of a search, and every other node represents a specific unique path from the starting node to a vertex in the original graph. The children of a node in the search tree represent the continuation of that path by following a single edge.
	- Because there can be multiple distinct paths to the same vertex in the original graph, a single vertex from the original graph may appear multiple (and a possibly infinite number of) times as distinct nodes within the search tree.

### Unweighted search

Basic Search algorithms

- **Depth-First Search** (**DFS**): Expands the deepest node. 
	- The frontier is implemented using a stack.
- **Breadth-First Search** (**BFS**): Expands the shallowest node. 
	- The frontier is implemented using a queue.

Traversal Orders

- For an ordered binary tree, depth-first traversals are uniquely categorized by when the current node (the root of a subtree) is visited (or "processed") relative to its children.
	- **Pre-order traversal**: Visit the current node first, then recursively traverse the left subtree, and finally recursively traverse the right subtree. (Root, Left, Right).
	- **In-order traversal**: Recursively traverse the left subtree, visit the current node, and finally recursively traverse the right subtree. (Left, Root, Right).
	- **Post-order traversal**: Recursively traverse the left subtree first, then the right subtree, and finally visit the current node. (Left, Right, Root).
- These concepts roughly generalize to ordered $k$-ary trees as well (where $k > 2$).

### Weighted Search

Basics

- We use $g(n)$ to denote the minimum cumulative path cost from the start node to node $n$. We use $h(n)$ to denote a heuristic function, which estimates the cost from node $n$ to a goal node. Finally we use $f(n)=g(n)+h(n)$ to denote the estimated cost from the start node to the goal node via some node $n$. 
- **Dijkstra's Algorithm**, often generalized as **Uniform-Cost Search** (**UCS**): Expands the node with lowest $g(n)$. This guarantees the shortest path from a starting node to all other nodes in a graph with non-negative edge weights. 
- **Greedy Best-First Search** (**BestFS**): Expands the node with lowest $h(n)$.
- **A\* Search**: Expands the node with lowest $f(n)$. 

Heuristics

- **Informed Search** refers to any search that relies on some heuristic $h(n)$.
- Heuristic $h(n)$ Properties:
    - Admissible: never over-estimating true cost
        - $0 ≤ h(n) ≤ h^*(n)$ where $h^*(n)$ is the true cost to the goal
        - Heuristics are usually solutions to relaxed problems, where constraints from the original problem have been removed to ensure they estimate a lower bound.
    - Consistent (or monotonic): never over-estimating the growth of the path cost
        - $h(n) ≤ h(n’) + c(n, n’)$ where $c(n, n’)$ is the actual cost to get from $n$ to $n’$
    - Consistent (sufficient) $\implies$ Admissible (necessary)
    - A* finds the optimal solution if and only if the heuristic is admissible
    - $h_1 ≥ h_2$ ($h_1$ dominates $h_2$) if $\forall n : h_1(n) ≥ h_2(n)$
        - Larger is better, as long as both are admissible.
    - You can combine heuristics with max, to get one that dominates both.
        - $h(n) = \max\{h_1(n), h_2(n)\}$ , then $h(n) ≥ h_1(n)$ and $h(n) ≥ h_2(n)$
