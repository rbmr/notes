### Preliminary Knowledge

This note assumes familiarity with entropy and relative entropy ([[1. Entropy and Information Measures]]).

### Codes

- A **source code** for a random variable $X$ assigns to each value $x$ a binary string (**codeword**) $c(x)$, with length $l(x)$.
- A code is a **prefix code** (or **instantaneous code**) if no codeword is a prefix of another. Prefix codes can be decoded on the fly, symbol by symbol, without looking ahead: as soon as a sequence of received bits matches a complete codeword, it cannot possibly be the start of a longer one, so it may be decoded immediately.
- Picture a codeword of length $l$ as a leaf at depth $l$ of an infinite binary tree (left/right branches = bit 0/1). The prefix condition says exactly that no codeword's leaf is an ancestor of another codeword's leaf.

### Kraft's Inequality

- **Kraft's inequality**: a binary prefix code with codeword lengths $l_1,\ldots,l_m$ exists if and only if
	$$
	\sum_{i=1}^m 2^{-l_i} \le 1
	$$
- Necessity (a prefix code's lengths must satisfy the inequality):
	1. Associate to each codeword $i$ (length $l_i$) the half-open interval $J_i = [0.c_i,\, 0.c_i+2^{-l_i}) \subset [0,1)$, where $0.c_i$ is the binary fraction formed by treating the codeword $c_i$ as bits after the binary point. This interval has length exactly $2^{-l_i}$, and consists of precisely the points in $[0,1)$ whose binary expansion begins with $c_i$.
	2. If codeword $i$ is not a prefix of codeword $j$ (and vice versa), their intervals $J_i,J_j$ are disjoint: any point in both would have a binary expansion starting with both $c_i$ and $c_j$, forcing one to be a prefix of the other.
	3. Since the prefix property holds for every pair, the intervals $J_1,\ldots,J_m$ are pairwise disjoint subsets of $[0,1)$, so their lengths sum to at most $1$: $\sum_i 2^{-l_i} \le 1$.
- Sufficiency (any lengths satisfying the inequality can be realized by some prefix code): order the lengths $l_1\le l_2\le\cdots\le l_m$, and assign interval $J_i = [s_{i-1}, s_{i-1}+2^{-l_i})$ where $s_{i-1} = \sum_{k<i} 2^{-l_k}$; the hypothesis $\sum_k 2^{-l_k}\le 1$ guarantees these intervals fit inside $[0,1)$ without overlapping, and each interval's left endpoint's first $l_i$ bits give a valid codeword of length $l_i$ with the prefix property (by the same argument as step 2, run in reverse).

### Optimal Codes and the Source Coding Theorem

- The **expected length** of a code for $X\sim p$ is $L=\sum_x p(x)l(x)$. An **optimal** prefix code minimizes $L$ subject to Kraft's inequality.
- **Lower bound**: for any prefix code, $L \ge H(X)$.
	1. Let $c=\sum_x 2^{-l(x)}\le 1$ (Kraft's inequality), and define $q(x) = 2^{-l(x)}/c$ — a valid probability distribution over the same values as $X$.
	2. Compute $L-H(X) = \sum_x p(x)l(x) - \sum_x p(x)\log\frac1{p(x)} = \sum_x p(x)\log\big(p(x)\cdot 2^{l(x)}\big) = \sum_x p(x)\log\frac{p(x)}{2^{-l(x)}}$.
	3. Rewrite $2^{-l(x)} = c\,q(x)$: $L-H(X) = \sum_x p(x)\log\frac{p(x)}{c\,q(x)} = \sum_x p(x)\log\frac{p(x)}{q(x)} - \log c = D(p\|q) - \log c$.
	4. Both terms on the right are $\ge 0$: $D(p\|q)\ge 0$ by Gibbs' inequality, and $-\log c \ge 0$ since $c\le 1$. Hence $L-H(X)\ge 0$.
	- Equality requires $D(p\|q)=0$ (so $p=q$) and $c=1$, i.e. $l(x)=\log\frac1{p(x)}$ exactly for every $x$ — only possible when every probability is a power of $\frac12$.
- **A code achieving $L < H(X)+1$ always exists**: take $l(x) = \left\lceil\log\frac1{p(x)}\right\rceil$ for each $x$ (round the "ideal" length up to an integer).
	1. Kraft's inequality holds: since $l(x) \ge \log\frac1{p(x)}$, we get $2^{-l(x)} \le p(x)$, so $\sum_x 2^{-l(x)} \le \sum_x p(x) = 1$.
	2. By definition of the ceiling, $l(x) < \log\frac1{p(x)}+1$.
	3. Taking expectations of step 2: $L = \sum_x p(x)l(x) < \sum_x p(x)\left(\log\frac1{p(x)}+1\right) = H(X)+1$.
- Together, these two bounds are **Shannon's source coding theorem** (noiseless case): the optimal expected code length $L^*$ satisfies $H(X) \le L^* < H(X)+1$. Coding blocks of $n$ symbols at a time and dividing by $n$ squeezes the overhead $\frac1n$ arbitrarily close to zero, so the achievable rate (bits per symbol) can be pushed arbitrarily close to $H(X)$ from above — matching the AEP's picture of roughly $2^{nH(X)}$ "typical" sequences each needing about $nH(X)$ bits to distinguish (see [[2. Asymptotic Equipartition Property]]).

### Huffman Coding

- **Huffman's algorithm** constructs an optimal prefix code directly, without solving any relaxed/rounded length formula:
	1. Start with one node per symbol, labeled with its probability.
	2. Repeatedly take the two nodes with the smallest probabilities, and merge them into a new node whose probability is their sum (and whose two children are the merged nodes), until a single node (the root) remains.
	3. Each symbol's codeword is the sequence of left/right branches (0/1) from the root to its leaf.
- **Optimality sketch**: an optimal prefix code can always be rearranged, without increasing its expected length, so that (a) the two least likely symbols have the longest codewords and are siblings (differ only in their last bit) — otherwise swapping a longer codeword assigned to a more likely symbol with a shorter one assigned to a less likely symbol would strictly decrease $L$; and (b) merging that sibling pair into a single symbol with their combined probability, and optimally coding the resulting smaller problem, reconstructs an optimal code for the original problem, by the same swap argument applied one level up. Since the merge step is exactly Huffman's construction, induction on the number of symbols shows the resulting code is optimal at every step.
- Huffman coding achieves the true optimal $L^*$ (not merely the $H(X) \le L^* < H(X)+1$ bound above), but $L^*$ can still exceed $H(X)$ whenever probabilities are not exact powers of $\frac12$; coding longer blocks of symbols closes this gap, as noted above.
