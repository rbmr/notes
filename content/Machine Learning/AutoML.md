### Metalearning for Hyperparameter Optimization

Hyperparameter optimization (HPO), combined with algorithm selection (AS), becomes combined algorithm selection and hyperparameter optimization (CASH). Completely automating this process is referred to as automatic machine learning (AutoML). Because hyperparameter effects are complex and dataset-dependent, metalearning aims to leverage prior experimental knowledge across tasks to make better design decisions.

Let $\mathcal{L}(a,\theta,d_{train}, d_{val})$ be the loss of an algorithm $a$, trained using some hyperparameters $\theta$, on the training data $d_{train}$, when evaluated on the validation data $d_{val}$. We want to find the values of $a$ and $\theta$ from their respective sets of algorithms $A$ and hyperparameter configurations $\Theta$ that minimize the loss.
$$
(a^*, \theta^*) = \mathop{\arg\min}_{\theta\in\Theta, a \in A}\ \mathcal{L}(a,\theta,d_{train},d_{val})
$$

The anatomy of a hyperparameter optimization system generally consists of two main components: 
- **Proposer Component** responsible for suggesting which hyperparameter configurations to test. 
- **Evaluator Component** responsible for efficiently evaluating the suggested configurations and determining which is optimal.

### Hyperparameter Proposal

**Grid Search** exhaustively tests a predefined, discretized set of hyperparameter configurations. You define a set of possible values for each hyperparameter, and the algorithm tries every combination of hyperparameter values. The main downside being its poor scalability since the number of configurations grows quickly in the number of hyperparameters, and the size of their respective domains. 

**Random Search** randomly samples the hyperparameter configurations from some predefined distribution. You don't need to run the algorithm for some fixed amount of time, running for longer just increases the probability you get some top $x\%$ configuration.

Also, suppose some hyperparameters are irrelevant (have little impact on the loss), then grid search re-runs many essentially equivalent configurations. Random search largely avoids this redundancy due to its variation in hyperparameter configurations. A significant issue that concerns both methods is that even when we determined a specific hyperparameter configuration performs poorly, we still keep trying similar hyperparameter configurations, wasting compute.

**Bayesian Optimization** is a sequential model-based optimization (SMBO) method that learns from the observed performance of previous hyperparameter configurations. It uses this history to fit a regression model (often called a **surrogate model**), to predict how well unseen configurations might perform. To decide which configurations to sample next, Bayesian Optimization relies on an acquisition function that balances exploration and exploitation.

 Instead of sampling the first hyperparameter configurations randomly, **portfolio design** looks at other datasets to find configurations that have historically worked well and applies them to a new but similar problem. The goal is to select a set of configurations that are fast to evaluate and provide strong performance.

**Metafeatures** are characteristics used to describe a specific task or dataset. Examples include the number of samples, the size of the majority class, or the kurtosis of numeric attributes. By comparing metafeatures, systems can estimate the distance or similarity between datasets to transfer knowledge effectively. Extracting these features can also be done using ML. 

**Metalearning** fundamentally means "learning how to do machine learning on the vast amounts of data generated by past machine learning experiments". To evaluate a meta-learning system several metrics are utilized:
- **Average regret**: measures the difference between the loss of the selected algorithm, versus the best possible loss for a dataset, averaged across all datasets for a fixed budget.
- **Normalized average regret** scales these losses to a range of $[0,1]$ before calculating the regret, preventing datasets with massive loss scales from skewing the results.
- **Average Rank** converts raw performance metrics into relative ranks across different optimization algorithms and averages these ranks across all datasets. This metric is highly dependent on which competing algorithms are included.

### Hyperparameter Evaluation

**Multi-fidelity** techniques accelerate the optimization process by first evaluating hyperparameter configurations on small samples of the data, and/or a simplified version of the problem, and reserving full evaluations only for the most promising candidates.  

**Successive Halving** (**SH**) aims to evaluate a large collection of hyperparameter configurations efficiently, it works as follows:
1. Each configuration is allocated a small initial budget, which can be measured in runtime, processing steps, or epochs. 
2. Once the initial budget is exhausted, the configurations are ranked by their performance, and the bottom half is eliminated. 
3. The surviving configurations continue training with their budget duplicated.
4. Steps 2-3 are repeated until only one single optimal configuration remains.

A practical drawback of successive halving is that the number of required machines changes at each stage, making parallelization inefficient. Asynchronous successive halving resolves these issues, handling an arbitrary number of workers, accommodating workers starting or stopping at different times, and can be safely halted at any point during the search.

Successive halving is also highly sensitive to the initial budget, if a configuration requires a larger budget to demonstrate its true potential, it might be prematurely eliminated. **Hyperband** addresses these challenges by running successive halving multiple times, where each run uses different settings for the initial number of configurations, the budget, and the halving factor. Hyperband provides the theoretical guarantee that it will not take no more than a log-factor of time compared to standard random search to achieve the same result.
